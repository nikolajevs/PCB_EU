# Правила работы с PCB_EU

## Репозиторий и область работы

- Репозиторий: `nikolajevs/PCB_EU`, основная ветка `main`.
- Это самостоятельный проект PCB_EU: аппаратная часть в `hardware/PCB_EU/`, прошивка в `softwareEU/`, тесты интерфейса в `tests/`.
- Первоначальный импорт в пустой репозиторий создаёт `main`. Последующие задачи начинать от свежего `origin/main` в отдельной ветке; публиковать PR и сливать после проверки и ревью.
- Предыдущая история находится в `nikolajevs/ai`. Для сборки этот репозиторий не требуется.
- Документация, названия и описания PR, ответы Игорю — на русском. Заголовки коммитов — на английском.

## Решения владельца

- Не менять схему, плату или BOM без соответствующей задачи.
- Закупка только в Salvats, Electrobase, Semikom и Lemona (решение 23.10.2026). Цены в EUR с НДС и датой проверки.
- Бюджет: ориентир 80 EUR, предел 100 EUR с НДС и доставкой. PCB, БП, нагрузки, инструменты и внешняя термозащита в него не входят. Текущая оценка — в README аппаратной части.
- Физическая сборка, нагрев, изоляция радиатора и работа прошивки на плате требуют стендовых испытаний; не объявлять их подтверждёнными по программным проверкам.

## Исходники и проверка

- `hardware/PCB_EU/tools/generate.py` создаёт схемы, проект, библиотеку символов, design.json и BOM. Изменять генератор и регенерировать результаты, не править их вручную.
- PCB воспроизводится скриптами `build_board.py`, `route_power.py`, `route_board.py`, `silkscreen.py`; подробности и ограничения — в README аппаратной части.
- Без KiCad: запускать `python hardware/PCB_EU/tools/generate.py` и `python hardware/PCB_EU/tools/verify.py hardware/PCB_EU/review/netlist.xml`. Если генератор не изменён, результат не должен содержательно меняться.
- Полный прогон: `hardware/PCB_EU/tools/run_checks.py`, KiCad 10.0.7, Python с `pcbnew` той же версии и Shapely 2. Другая версия требует явного `--allow-other-version`.
- `hardware/PCB_EU/review/` хранит последний полный аппаратный прогон. Обновлять отчёты только полным прогоном, отмечать устаревшие данные в README. Не представлять сохранённые отчёты как результат нового запуска.
- Команды сборки и зависимости прошивки — в `softwareEU/README.md`; тесты интерфейса: `node --test tests/settings.test.cjs`.
- В PR перечислять выполненные и не выполненные проверки. Не публиковать секреты и локальные настройки.
- Сложные конфликты схемы и платы не разрешать автоматически. Для генерируемых схем объединять исходники генератора и повторять генерацию.
- Долговременные решения записывать в существующие README и DESIGN.md; отчёт о задаче — в PR. Устаревшие сведения удалять, история сохраняется в Git.
